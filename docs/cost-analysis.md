## 3. Оптимізації (2–3 знахідки)

### Оптимізація 1 — Вузький контекст замість повного skill

| | Токенів input/turn | Вартість 11 turns (input) |
|---|---:|---:|
| **До:** skill цілком + `app/` | ~65 000 | ~$2,15 |
| **Після:** `@app/hooks` `@app/components` + `SKILL.md` | ~15 000 | ~$0,50 |
| **Економія** | **−50 000 tok/turn** | **~$1,65** |

**Дія:** у промпті явно вказувати `@app/hooks/useNotes.ts`, `@app/components/`, `app/AGENTS.md`; skill читати через `SKILL.md` (1 764 tok), а не весь `.agents/skills/.../` (57 531 tok). Не тегати `public/*.svg` — вони не потрібні для логіки нотаток.


### Оптимізація 2 — Дешевша модель для рутини

| Задача | Модель | Орієнтовна вартість |
|---|---|---:|
| «Прочитай AGENTS.md і опиши проєкт» | Fast / Auto | ~$0,05 |
| «npm run lint / build, виправ помилку» | Fast / Auto | ~$0,08 |
| Реалізація фічі з 6 AC | Agent (Sonnet/Opus) | ~$2,50–3,00 |

**Дія:** Plan + опис проєкту + lint-fix — у **Ask/Fast**; повний **Agent** лише для імплементації за готовим планом. На цій домашці це могло б зберегти **2–3 turns** на дорогій моделі (~**$0,40–0,60**).

### Оптимізація 3 — Чіткіші промпти + коротші ітерації (Plan → Agent)

| | Turns | Причина зайвих turns |
|---|---:|---|
| **Без AC** (гіпотетично «зроби notes app») | ~15–18 | уточнення scope, переробка UI, missing edit/delete |
| **З AC + Plan mode** (фактично) | ~11 | 1 turn на lint (`useEffect`), 1 на `getServerSnapshot` |
| **З AC + вузький контекст** (прогноз) | ~8 | менше «шуму», точніші зміни з першого разу |

**Дія:** перед кодом — 6 AC у Plan mode (зроблено в Task 2); у Agent передавати лише план + файли фічі. Формула промпта: *роль + файли + AC + обмеження (localStorage, без backend)*. Це зменшує ітерації на **~25–30%**.

**Додатково:** додати `repomix-output.xml` і `repomix-*.xml` у `.cursorignore` — інакше один артеfact = **+145 000 tok** у контексті.

## 4. Висновки

1. **Найбільший важіль — розмір контексту, не модель.** Skill цілком (57,5k tok) у **18×** більший за код фічі (3,1k tok). Вузький `@`-контекст дає **~75%** економії на фічі такого масштабу.

2. **Plan mode окупається.** Acceptance criteria до коду скоротили scope creep (edit/delete/localStorage узгоджені заздалегідь) і уникнули повного переписування. Навіть з 2 bugfix-turns сесія вкладається в ~11 turns замість потенційних 15+.

3. **Артефакти repomix не можна комітити в контекст IDE.** Файл `repomix-full.xml` (145k tok) робить «репозиторій» 225k tok — вимір контексту стає нерепрезентативним і дорогим. Тримати output repomix поза `.cursorignore` / `.gitignore` — помилка для AI-assisted workflow.
